2. Starting Point

  • Declaration: Built from scratch specifically for the TrueFoundry Forge-a-thon using the official VS Code Extension API (vscode), Model Context Protocol TypeScript SDK (@modelcontextprotocol/sdk), and diff.
  • Zero Upstream Agent Loops: We did not fork an existing coding agent harness (e.g. Cline, Roo Code, or Continue backend). 100% of the agent loop runs entirely on TrueForge (http://localhost:8790). The extension is strictly an editor-native client, UI shell, and MCP tool provider.
  • UI/UX Design Language: The visual ergonomics draw inspiration from the clean, ergonomic interface conventions of Continue (collapsible tool invocation cards, streaming bubbles, syntax-highlighted diff review cards, and instant model switching), custom-engineered to bind directly to TrueForge's SSE stream and approval events.

  • Communication Flow: The extension communicates over TrueForge's public HTTP REST and SSE APIs (POST /api/v1/sessions, POST /api/v1/sessions/{id}/turns, POST /api/v1/sessions/{id}/cancel).
  • Embedded Streamable HTTP MCP Server (vscode-editor): Runs on http://127.0.0.1:8791/mcp. Automatically registered with TrueForge via PUT /api/v1/settings/mcp-servers on activation. TrueForge is configured with OUTBOUND_URL_ALLOWED_HOSTS='["localhost","127.0.0.1"]' to permit loopback tool calls.
  • Exposed MCP Tools:
    • Preloaded (Eager): assemble_context (lexical/AST ranker with token budget), search_workspace (regex search), read_file (line-bounded reader).
    • Deferred (preload: false): list_files, get_symbols, propose_edit (diff modification requiring approval), run_command (virtualenv-aware shell requiring approval), git_status.
  • Harness Features:
    • Deferred Tool Loading: Heavy tools are marked preload: false, loaded dynamically via TrueForge's call_tool wrapper, saving ~1,500 prompt tokens per turn.
    • TrueForge Tool Approvals: Configured for ["propose_edit", "run_command"]. When tool.approval_required emits, generation pauses and interactive diffs render inside VS Code before returning { approved: true/false }.
    • Compaction & Safeguards: Automatic context compaction enabled at threshold 0.85. assemble_context caps output at 4,500 tokens, safely preventing TrueForge's 24,000-character tool response truncation.

4. How Context Is Selected

Context selection is the intellectual core of TrueForge Coder. On large codebases like pallets/flask (17,000+ LOC), full concatenation exhausts context windows. We implement a multi-signal ranker strictly constrained by a token budget:

Workspace Files (217 files)
           │
           ▼
[ AST Symbol Parsing & Path Analysis ]
           │
           ▼
[ Multi-Signal Relevance Scoring ]
  Score = 40.0 * ExactSegmentMatch + 15.0 * StemmedSegmentMatch + 25.0 * ASTSymbolMatch
        + 30.0 * ArchitecturalRoleMatch + 10.0 * BM25/IDF Lexical + 1000.0 * Explicit Mentions
           │
           ▼
[ Priority Knapsack Capped at 4,500 Tokens (~16,500 Chars) ]
  ├─► Selected #1: src/flask/cli.py   (1,147 tok, Score: 125.4) [Core Click commands]
  ├─► Selected #2: docs/cli.rst       (1,268 tok, Score: 114.8) [CLI documentation]
  ├─► Selected #3: tests/test_cli.py  (1,017 tok, Score: 110.6) [CLI test suite]
  ├─► Selected #4: tests/test_json.py (1,008 tok, Score: 71.1)  [JSON serialization]
  └─► Excluded by Budget: src/flask/json/tag.py, tests/test_config.py...
  • Multi-Signal Scoring: Evaluates exact path tokens, AST function/class definitions, architectural role pairings (implementation + docs + tests), and lexical TF-IDF. Direct @file and @symbol mentions receive a $+1,000.0$ boost.
  • Budget Knapsack (4,500 Tokens): Accumulates top-ranked files until the budget is saturated. Excluded candidate files are concisely listed in an Excluded by budget block to grant context awareness without token waste.
  • Visible UI Reporting: The purple Context Assembly card renders live in the sidebar: 4440 / 4500 tok Capped (99%) with itemized rationale for every selected file and the list of excluded paths.

5. Model Setup

  • Models Used:
    • Primary: google-gemini/gemini-3-5-flash-lite (via Google AI Studio through TrueForge catalog provider).
    • Fallback: google-gemini/gemini-3-1-flash-lite (via Google AI Studio through TrueForge catalog provider).
    • Fault Injection / Test Model: invalid-primary/invalid-key-model (configured with an invalid key to test resilience).
  • Approximate Cost: Both Gemini 3.5 and 3.1 Flash Lite run within Google AI Studio's free tier. Paid pricing is $0.075 / 1M input tokens and $0.30 / 1M output tokens. Total development, test runs, and rehearsal cost: ≈ $0.04 USD.
  • How a User Switches Models:
    • Dropdown Selectors: Header dropdowns populated dynamically via GET /api/v1/models allow 1-click model switching.
    • Automatic Resilience Fallback (Task C): If the primary model fails (401/404/503), the extension captures the failure, keeps the editor completely responsive, displays an amber ⚡ Automatic Resilience Fallback card, and automatically re-routes execution to the fallback model with zero user intervention while git status remains clean.

7. Tools Used

  • TrueForge (@truefoundry/trueforge): Local agent harness running on localhost:8790.
  • VS Code Extension API (vscode): Editor host, TextDocumentContentProvider for virtual diffs, CodeLensProvider, and WebviewViewProvider.
  • Model Context Protocol SDK (@modelcontextprotocol/sdk): TypeScript implementation of Streamable HTTP MCP server.
  • diff library: Unified diff parsing, hunk splitting, and reverse hunk patching for atomic Undo.
  • esbuild: High-performance TypeScript bundle compilation.
  • Antigravity AI Assistant (Google DeepMind): Used for architecture consultation, pair programming, and automated verification scripts.
  • Python Virtualenv (flask-venv): Python 3.12 with pinned pytest==8.3.5 and editable Flask 3.1.3.

8. Known Limitations & What We Would Do With Another Month

Known Limitations

  1. Tool Response Envelope Ceiling: TrueForge enforces a 24,000-character ceiling on large_tool_response. While our 4,500-token context budget safely prevents overflow, an exceptionally large single-file diff spanning thousands of lines requires multi-turn chunking.
  2. Heuristic Context Ranking vs. Deep Semantics: Our context assembler uses BM25, exact path heuristics, and regex AST symbol extraction. While fast (<80ms) and effective on Flask, it lacks deep cross-file type resolution (e.g., following dynamically imported class hierarchies).
  3. Sequential Hunk Acceptance Dependency: Accepting hunk N when earlier hunks in the same file were rejected requires line-offset reconciliation. While our bottom-to-top reverse hunk application correctly handles independent hunks, overlapping multiline edits can produce merge conflicts.

What We Would Build With Another Month

  1. Language Server Protocol (LSP) Cross-Reference Integration:
    • Integrate directly with VS Code TypeScript/Pyright language servers via executeDefinitionProvider and executeReferenceProvider.
    • Augment the context assembler with true call-graph and type-dependency DAGs, providing mathematically complete context slices for multi-module refactors.
  2. Local Vector Hybrid Index (SQLite-vec + BM25):
    • Embed a lightweight, local ONNX embedding model (all-MiniLM-L6-v2) writing to an embedded SQLite-vec database.
    • Implement Reciprocal Rank Fusion (RRF) combining dense semantic search with sparse lexical retrieval for instant semantic symbol search.
  3. Upstream Contribution to TrueForge (Round 2 Preparation):
    • Build first-class Interactive Tool Progress & Streaming Approvals into the TrueForge harness: currently, approval pausing halts the SSE turn stream until resolved. We would contribute an asynchronous sub-stream protocol allowing background tools to continue planning while the user evaluates a file diff.
    • Enhance TrueForge's MCP client to natively unwrap complex deferred tool envelopes without requiring custom client unwrapping.
